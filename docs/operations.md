# 使用与升级 · 0.1.1

## 固定技术基线

解释器由 .python-version 指定 CPython 3.12.13，uv 0.12.2 解析和验证 uv.lock。直接依赖为 Deep Agents 0.7.5、LangChain 1.4.3、LangGraph 1.2.12、langchain-core 1.6.5 和 langchain-openai 1.6.6。业务包可选择所获授权的工具调用模型，适配端点须支持 OpenAI 兼容的工具调用。使用组织模型时由开发者在进程外注入凭据。

init 创建全新独立目录，复制该发行版的运行时、锁和开发资产。脚手架没有指向开发者个人目录的依赖。首版将运行时代码随项目固定，通过版本清单检查框架文件是否漂移。升级同时验证 Python、锁、引擎和业务结果。

## CLI 与能力边界

命令前缀为 `uv run --locked python -m foundry`。

| 子命令 | 行为 |
| --- | --- |
| init DEST [--example dispatch] | 生成空白业务包或已填写的示例。目标须为新目录 |
| doctor | 列出解释器、框架、工具注册表、Skill 目录及模型配置存在性；不发送模型请求 |
| chat [PROMPT] | 单次提问或进程内多轮会话，输入 /quit 退出。每个会话独立 |
| eval [--case ID] [--fixture] [--out DIR] | 同一题的多轮共享会话，各题独立启动；单独运行目录持续保存实际尝试，完成后统一给退出码 |
| compare BASE CANDIDATE | 比较两次同题同模式运行的自动检查结果；拒绝复用同一次尝试或混用不同判据 |
| upgrade OLD NEW | 从新发行目录创建并行候选；目标已有文件时停止。旧项目保持可运行 |

0 表示命令完成且适用的自动检查通过，1 表示已评测且有失败或错误，2 表示输入、环境或依赖不满足。模型依赖错误与业务断言失败在每次尝试内分别记 error 和 fail。进程被中断时 run.json 保留 running 及已完成尝试；新运行另取 ID。真实运行前用 doctor 检查环境，随后用一题验证实际模型和依赖接线。

图通过内存 checkpoint 支持同进程会话；跨进程重启后的业务恢复需在具体宿主接持久存储并实测。运行时仅挂载该业务的 skills/，经工具读取，挂载区域禁止写入。其余临时文件在会话内存中；项目根、开发规则和 Oracle 不挂载。Python 业务工具是本机可信程序，可以访问业务依赖，权限与副作用由工具所有者控制。

## 评测与证据

使用已脱敏、获准记录的用例与模型可见资料。eval 会保存完整问题、模型输入、工具 schema、提案、业务工具回执与答复。trace 文件留在本机的独立运行目录，发布 ZIP 排除运行记录。将底层实发证据与独立真值通过业务回执的引用关联；回调层的入参不证明远端已经成功执行。外部数据变化、采样配置、身份及权限须另行核对并冻结。自动对照只能检查记录中的条件。

每个 attempt 附带 AgentGauge 0.4.0.dev10 Trace 结构的 agentgauge-trace.json，包含原始事件、逻辑轮次、工具调用、用户答复及运行耗时；业务检查仍在 run.json。组织内完整 runner、recorder、封存与在线发布属于可选集成，公共源码包不分发内部 wheel。这是一份 Trace 交换产物，不等价于 AgentGauge 平台已封存的完整 Run。

使用受控模型可在无密钥环境检查安装、Skill 加载、工具分派、状态与证据链。开发者在 evals/simulation.py 中实现 make_model() 供 --fixture 使用，真实模型路径不会导入该文件。模型上线质量须实际运行并复核完整交付。人工或 reviewer 裁定单列于 Checklist，保留原自动得分和来源。

## 升级与回退

在旧版保存当前冻结运行。由新版 upgrade 验证旧发行清单与接入契约，拷贝 business/、evals/、SPEC.md、CHECKLIST.md 和业务 README 到新候选。框架定制、未知额外文件及业务符号链接需要先审阅，以免丢失原工作。旧运行、Git 历史、环境文件和虚拟环境保留在原目录。复验时从各自目录启动，保持数据版本、模型、权限和用例可比，同时核对性能与相邻回归。切回旧目录即可回退。变更公共接入契约的下一主版本应先提供迁移说明，并用实际旧项目做升级测试。

开发用 Skill 和 reviewer 工作在 Codex 项目作用域；实施时核对实际发现与加载情况。业务运行所用 system.md 和 Skill 与开发资产独立。运行需获得相应业务授权。发行验收另需真实模型与独立开发者在干净宿主上完成一个未见场景，记录耗时和需要原作者解释的事项。
