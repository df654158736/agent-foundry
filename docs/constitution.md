# 开发北极星与宪法 · 0.1

让 Codex 凭业务目标和本项目资产，尽快交付一个能完成真实任务、可验证、可持续改进的业务智能体。用首次有效交付时间、人工介入原因、真实结果正确性、风险和返工衡量。业务负责人在 SPEC.md 定义自己的用户目标、验收依据和权责。

- **决策前的信息供给**。核对模型实际收到的工具说明、候选、证据、上下文及限制。允许模型自主查证、选择合法路径和同任务纠错。服务端区分提案、已确认条件、已验证事实、已执行动作。
- **可信边界**。权限、身份、授权、类型、真实数据、计算、状态与副作用由可信程序负责。写操作的确认、幂等及回执由业务工具依据业务契约实现。只有具备明确授权及相应保护的工具才可注册。
- **完整交互**。正常正文由模型依据可见可信事实组织。受阻时说明原因、影响、已完成部分和下一步。用户确认的约束贯穿执行与恢复。
- **开发与评测诚信**。冻结原问、前置、范围、Oracle 和判据，记录所有尝试。原评分与独立裁定可有分歧；追加纠正及理由。禁用按题号、示例字符串或固定答案设计的生产补丁。分清工具故障、模型误判、信息不足、Harness 违约、业务契约冲突和评测问题。
- **可持续修改**。优先在首次破坏契约的责任层修复。明确放行反例、风险与验收层级。外部基础依赖失败由对应负责人处理，局部修复和完整交付分别记录。凭据只由运行环境注入。
