# 智能体 Harness 真链开发与调试

以真实用户目标和可追溯的执行过程验证契约。先读取本发行版的 [goal-aligned-design](../goal-aligned-design/SKILL.md) 并应用其第一准则：让模型拥有正确判断的依据；正确归因、保障正常人机交互；模型自主表达，服务端守护可信事实。金标只是验收样本，不是生产规则或场景白名单。

## 工作入口与授权

按任务实际需要读取参考，不要求全量加载：

| 任务 | 按需阅读 |
|---|---|
| 金标适用性、跨阶段证据、评测或契约质疑 | [证据台账](references/evidence-ledger.md) |
| 全量、多项目、跨版本回归 | [全量金标真链回归](references/full-suite-reallink.md)，先冻结批次并验接线 |
| 修复、重构或审查生产逻辑 | [通用修复检查](references/harness-repair-generalization.md)，落实不变量、责任和反例 |
| 某类智能体的专有风险 | [智能体类型检查项](references/agent-type-checklist.md) 的对应小节 |

诊断与审查只在授权范围内取证、复现并报告；评测不自动授权修代码，修复不自动授权部署。未经授权不修改共享数据、本体、指标、权限、索引、配置、需求或验收口径。基础缺口移交相应 owner。以下是评测者的工作方法，不是线上智能体的固定运行步骤。

## 一、确认契约与运行基线

- 读取相关项目规则、有效需求/Spec、已确认设计决策和实际配置，不用 Spec 或金标的文字替代用户共识。明确原问、上下文、真实身份/权限、项目/World、必要前置、目标行为、停止条件与允许变化的范围。
- 证明所测代码、制品/运行实例、实际模型及参数、prompt、Skill、工具、数据依赖一致；仓库中存在某能力不等于实际加载，提交、合入、部署与生效分别记录。定位正常入口、最小复现、模型原始记录、状态、服务实发和独立真值。
- 金标验收的是已确认能力：区分业务结果、过程契约与负路径，允许满足目标的不同合法路径。依赖不足记阻塞，契约不清记待确认；用 [金标适用性记录](references/evidence-ledger.md#金标适用性记录) 核对能力、前置和 Oracle。原始输入、判分、版本与失败记录不可静默替换或降级。

## 二、选择有判别力的验证层级

按风险从确定性函数/结构契约、模块回归、真实依赖集成，扩展到真实身份的正常入口与独立对账。涉及跨轮、写操作或恢复时检查状态、幂等性、重试和副作用，重放验证未被旧状态、缓存或残留进程污染；跨组件/配置变化需要实际接线证据。mock、fixture、契约/集成测试、历史真链、当前真实入口及生产影子分别标注。独立 Oracle 只证明业务真值，不能证明执行路径合规；终态成功也不能证明交付完整。无需机械跑全层；依赖或授权不足时完成可验证部分，说明缺口。

## 三、逐题还原七个决策截面

对相关截面记录预期、实际、首次差异、决策所有者、关键原始产物及证据位置。不同智能体可合并或省略不适用的截面，不要求固定工具顺序。

| 截面 | 核对什么 |
|---|---|
| 原问与设置 | 原文、偏移/槽位（适用时）、上下文、明确/否定/已确认约束、身份、版本与真实前置；不可丢失、私自改范围。 |
| 模型决策前 | 实际首次相关调用及后续决策前看到的 prompt、Skill、schema、业务事实、候选、约束、状态及查证入口，核对其来源、裁剪、默认值；后台有信息不等于模型看到。 |
| 模型提案 | 实际工具、路由、子智能体、参数、语义假设及依据；候选/召回不等于等义或用户授权，区分已知与未知。 |
| Harness 与工具回执 | 实际接受、规范化、冻结、拒绝/澄清、权限与预算判据；是否误拦、误替换、遗漏或空转；纠错反馈是否具体、可行动、保留其他条件并支持同任务继续；下游实际消费字段。 |
| 实发 | 比对提案、冻结/授权与实际依赖请求和原始返回，核验时间、范围、字段、值、类型、关系、路径及计算；写操作核对授权、范围、幂等和实际副作用。 |
| 独立对账 | 通过获准的独立权威数据/实现验证同身份、同口径与范围的结果；范围等价与数值/集合一致分开。不支持、空集、零、无权限、依赖失败、未执行不能混淆。 |
| 用户交付与续接 | 对比实际模型正文、可信事实投影、完成校验及真实用户可见结果。正常开放式正文由模型自主组织，不以模板/占位符代写，只有真实模型不可用等明确降级才用最低可信交付；检查事实/引用、覆盖、限制及受阻解释。核对状态写入、继承、清理、终止和跨轮可用性；续接题验证首个终态可见后立即关闭流，再发下一轮仍能获取必要状态。 |

### 观测面与证据关联

先查看原始产物真实字段、记录范围及截断/遗漏，核对别名、转发与动态派发；“没记录到”不是“没发生”。用 case/run/thread/turn/trace/span/task/request ID、原问和时间窗建立映射，防止并发串线或跨轮错配；关键疑点从独立观测面交叉核对。只读观测不能篡改模型回答或依赖结果。结合类型检查项比对数据结构、状态、来源、因果顺序、预算/时延与调用，不从 HTTP、工具名或最终文案反推执行。

## 四、按首次违约与责任归因

| 责任层 | 判定依据 |
|---|---|
| 信息供给 | 模型决策前缺少准确、可理解、可取得的依据，任务说明、参数 schema、候选或反馈不足/冲突。 |
| 模型能力/语义判断 | 已有充分、正确的可见依据、可行的合法路径与适用的纠错反馈，模型仍误判、猜填、漏条件或表达不实；不把第二模型推断升格为事实。 |
| 确定性 Harness | 提取、路由/编排、接线、适配、状态/恢复、客观校验或交付违约；正确提案被误拒、实际条件改变、模型可见可信事实在验收侧漏接等。 |
| 基础依赖、权限、数据或环境 | 合法请求下依赖未履约，或索引/能力/权限/数据、实际版本、认证、网络、服务不就绪；依据实际失败状态，不靠重启成功猜根因。 |
| Spec/产品语义 | 已确认目标或上下游契约与 Spec 冲突、实际能力语义未确认。 |
| 评测/Oracle | 金标、评分器、fixture 或 Oracle 不符合已确认契约，要求未约定的固定路径，或期望与数学、事实、权限、口径不符。 |

同一失败可有多层责任。错误参数本身不证明调用方有缺陷，先查实际可见依据、客观契约及纠错过程。关键决策前的模型输入无证据时，信息供给与模型能力的责任保持未证实；已经独立证实的执行、事实或状态违约仍可判定。基础受阻仍检查 Harness 是否保存原条件、已核实结果及真实错误类别，并让模型用正常语言讲清影响、未完成项和可行下一步；不以错误码或重试按钮代替交互，不伪造成功。

若 Spec/金标/Oracle 与已确认目标冲突，暂停相关生产修改，用 [质疑记录](references/evidence-ledger.md#规范或用例质疑记录) 提供原文版本、证据、责任、影响、方案及需确认的决定。保留冻结分数；确认后才变更基线并另批复验。无关且有授权的工作可继续。

## 五、获准时修通用不变量

按 [通用修复检查](references/harness-repair-generalization.md) 在首次违约的责任层定义共享不变量、可信判据、合法反例与影响面。不能证明规则覆盖或保护客观契约时，不为模型误判、单个 Bug 或金标增加词面门、强制工具/澄清、模板代写或样例补丁；不要用 prompt 掩盖确定性缺陷，也不放宽真实有效约束。保留已确认条件，给足信息与可行动反馈。修复验证首次错误的中间状态、未预设变体、反例和相邻回归，按风险复跑真实入口。归因为模型或依赖的问题保持真实记录；不要为追求百分百通过率反复补丁。

## 六、交付结论

以版本、入口、完整分母及脱敏证据为基础，逐题分开报告：

- 原冻结评分、实际业务正确性、用户交互/正文作者、信息供给、模型判断、Harness 契约及基础依赖；通过、失败、阻塞、待确认、未执行分列，正确受阻交互不等于业务金标通过。
- 关键预期/实际差异、首次违约证据、验证层级、责任与可修复事项；实现任务另列改动、共享不变量和回归结果。性能对照基于同输入、配置、依赖与真实分阶段耗时。
- 尚未验证范围、环境/权限缺口与下一步；中间版本、诊断变体、旧绿灯和单次模型成功不能代表最终版本或稳定性。

结论旁给出最直接、可打开的原始或脱敏证据；分清事实与推断。输出、日志、提交、测试和交接不得泄露密码、token、密钥或无关敏感数据。
