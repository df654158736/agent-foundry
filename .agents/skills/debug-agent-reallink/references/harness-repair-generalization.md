# 智能体 Harness 通用修复检查

适用于获准的新增、修复、重构及评审。根因、权限和验收按 [主 Skill](../SKILL.md)；本文件只处理生产逻辑如何正确设计、修改与回归。

## 1. 定义共享不变量

修改前写清：结构性症状、首次违约阶段、决策所有者、所有同结构合法输入应满足的不变量、可信输入、相似但不应触发的反例、合法其他路径与影响面（路由、工具、状态、跨轮、已有场景）。

合格的不变量描述结构和优先级，例如：

- 用户明确确认的选择覆盖模型此前的猜测。
- 指标切换时，只继承在新目标下仍有意义的时间范围。
- preview 与 execute 对同一可信基底使用相同范围判定。
- 外部服务失败的原始类别不能丢失或伪装成功。

不合格规则引用题号、特定客户/名称、固定编码、完整问句或期望答案。先有通用判据再写逻辑，不用样例反推生产规则。

## 2. 让拥有决策权的层负责

- 模型负责理解开放目标、选择和组合合法能力、提案和自主表达，不伪造权限、事实或工具结果；Harness 提供决策前实际需要的信息和可发现的查证入口。
- 确定性 Harness 负责权限、客观口径、状态/来源/优先级、预算、恢复、终止与可信证据完整性；工具适配层负责 schema、参数语义与可行动反馈，外部服务负责其业务事实和计算；评测器只测量，不参与线上决策或代它纠错。
- 合法提案按实际类型、已确认范围和证据核验，接受等价的单查、批查、证据复用等路径。校验不通过返回具体冲突、可用依据和合法下一步，保留其他条件，让模型自主修正。只有模型无法自行消除、会影响结果的真实歧义，或用户明确要求先选时才澄清。
- 正常正文交付使用模型自主组织、服务端可信事实/引用核验；披露和核验复用相同事实投影。失败也正常交互，按真实类别解释已核实结果、缺项和下一步。交付完整性按已绑定目标逐项结算，适用的受阻/降级不能虚报业务成功。

新增或保留硬门必须说明保护的真实共享不变量、独立可信依据、误拦合法请求的成本、通过/退回后模型能做什么。对开放语言不穷举词面；若无法覆盖全部合法表达，明确意义并比较收窄为辅助证据或移除的方案。只对客观契约规定的前置/顺序/格式施加约束；只修改首次破坏不变量的层。已确认目标不变且证据证明旧门无客观契约依据时，获准修复可直接在责任层移除或收窄；改变产品目标、业务契约或验收标准才需重新确认。

## 3. 识别补丁式修复

出现以下情形重新抽象，不以金标变绿为目标：

- 生产分支匹配题号、业务名称、固定 ID/编码、完整问句或答案；随问法无限扩充关键词、正则或例外表。
- 为单场景改变全局继承、排序、回退或停止条件却无反例；把合法路径强制成固定工具顺序、原话门、重复查证或确认。
- 用 prompt 掩盖确定性的权限、状态、幂等、schema 或错误分类缺陷；用服务端模板替代正常模型表述，或将其它模型的推断升级为用户确认/执行授权。
- 已有充分模型依据仍误判时增加特例、猜测口径或放宽有效客观约束；或者为“安全”保留没有真实契约依据的门。不要用 Harness 代偿基础依赖、数据或权限不足。
- 运行时未修复就放宽金标、评分或 mock；未获授权擅改产品语义、口径、数据或发布状态。

允许协议枚举、受治理词表、配置化策略及必要安全阻断是有限集合，但须说明权威来源、维护责任和缺省行为。限制本身是待审对象，不因旧代码存在就合理。

## 4. 用变体和反例验收

- **结构复现**：断言首次违约中间状态、真实回执、纠错动作与下游消费，而非只断言 success/答案。
- **合成变体与反例**：替换名称、编码、顺序、基数、数据规模、合法工具选择及结果表示，验证原应通过的请求不被误拦、真实冲突仍被核验。检查生产 diff 不含样例专有字面量。
- **相邻回归**：同一状态机、复用、恢复、交付或继承路径；断言证据权限、裁剪、预算、重试、终止、未解决项与写操作副作用。对话终态被客户端立即关闭的续接反例要在受影响场景检查。
- **真实入口**：按风险扩大至实际模型、身份、依赖、运行时生效与独立真值；非确定性模型输出验证稳定契约和用户目标，只有产品明确要求固定文案才逐字断言。

已证实模型、基础依赖或评测问题时按实际责任处理，不能据单个失败宣告 Harness 有缺陷；同一失败存在多个所有者时分别举证和修复。完成层级及业务/交互判据遵循主 Skill，不把局部测试、正确受阻或旧版本测试称作整体业务验收。
