# 全量金标真链回归

适用于全量、多项目或跨版本回归；通用诊断使用 [主 Skill 的七个决策截面](../SKILL.md#三逐题还原七个决策截面) 与 [证据台账](evidence-ledger.md)。本文件只增加批次执行的特有约束。

## 1. 冻结本次批次

- 从实际生效评测目录/发布清单枚举目标范围，记录项目、World/租户、target、去重规则及完整分母。仓库历史 YAML、延期试点与当前发布用例不是同一集合。冻结稳定 ID、原问/期望、版本或哈希、适用性、预设用户选择、Oracle、评分器/适配器，不按初跑结果改题、删除或替换。
- 固定被测提交、制品/镜像、实例、模型版本和参数、实际工具、系统/业务提示、Skill、记忆策略及依赖，必要时比对构建文件、运行时披露和代码。区分发布环境验收与本地候选测试，不跨版本混算。
- 多项目逐个确认真实成员身份/角色和数据前置；Oracle 使用同一合法范围，不能因能登录就换项目或越权。只阻塞受影响场景。
- 先用有判别力的小批验证入口、配置、记录器及 Oracle 接线。复用正规 runner、目录、适配器与回放工具；候选服务隔离任务状态、端口和临时存储，连接真实获准依赖，不修改共享配置。

## 2. 组织可恢复的运行

- 每题每次尝试独立 run/thread；多轮题只在题内复用会话。根据服务实际容量、时限和预算控制并发，避免测试自身诱发限流。只在真实出现且与冻结意图唯一匹配时提交预设用户选择；未定义的业务歧义如实记录。控制注入、模拟依赖、改写问句与故障反例单独标记，不冒充自然金标。
- 持续落盘每次原问、实际事件流、终态、评分、关联 ID、时间、模型及工具记录、业务实发和 Oracle；按完成记录断点续跑，保留所有尝试/重试原因与版本，不只保留最佳结果。
- 监控批次一致性。共同环境/观测异常时暂停受影响子批次定位，独立可执行项继续。先保存可信冻结基线；获准修复后另建版本批次，复验首次违约及相邻路径，再按风险决定是否重跑全量。不得靠无限重跑或挑选幸运结果掩盖模型问题。

## 3. 对照和汇总

- 按主 Skill 七截面记录实际逐题证据；不同版本、原始金标、诊断变体、执行次数与适用分母分开汇总，保留冻结评分及独立契约判断。最终制品没跑过的题不能拿中间版本通过宣告已验收。
- 以可比较的输入、配置、依赖和样本量核对改造前后：合法条件保留、首次信息供给、猜填/修改/纠错、真实必要/多余澄清、业务请求/检索调用、LLM 轮次、分阶段耗时与超时、实际结果和正文作者。记录实际采样/重试策略、有效和失败样本数；按样本量给范围、中位数或分位数，样本不足如实描述观察，不推断显著性。区分智能、自主性、正确性、交互与性能；调用少或文案短不自动等于更智能，个别慢也不能据此给架构归因。
- 输出清单、版本、证据索引、逐题差异与责任排序、未验证范围。停止仅本次创建的进程、服务和临时资源，保留脱敏证据，不影响其他会话。需要跨会话续跑时用 `session-handoff` 记录项目特有版本、访问方式（不含凭据）、真实入口、批次状态与证据路径，不把项目专有题号和业务值写进通用 Skill。
