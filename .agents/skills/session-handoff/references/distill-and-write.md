# 提炼知识并编写交接

本参考用于交出会话。接手现成交接只读resume.md及当前实际需要的项目材料。

## 从对话中提炼

先找用户当前要达成的结果和最新转向。用户指定了下一会话重点时，围绕该重点选择相关知识；没有指定时，沿用仍有效的未完成目标，不例行追问。保留会改变后续判断的背景，不按历史话题平均分配篇幅，也不把已经完成的工作编造成待继续任务。再围绕下列知识整理，不先写时间顺序总结再删字。

| 知识 | 需要保存的深度 | 噪音处理 |
|---|---|---|
| 目标/范围 | 当前交付物、负责边界、明确不做的相关内容；只保留影响此任务的偏好/规则 | 不复制无关历史任务或全部用户画像 |
| 已确定规则 | 有效行为、用户关键纠正、来源/确认者、适用条件、默认与例外、验收条件；结论改变过时留替代关系 | 多次确认合并；推测不能写成已批准 |
| 关键设计/调查结果 | 为什么这样做、已有可复用基础、具体缺口、接口/数据/状态关系、反例和仍存限制 | 保留影响实现的因果；删找文件、试命令的过程流水 |
| 已完成/进行中 | 实际交付与证据、当前执行边界、未提交/未发布的限制 | 计划、文档、实现、验收分别写，不能统称“完成” |
| 测试/数据/环境 | 测了什么及版本/环境/Oracle、结论的覆盖边界、未测与原因 | 大日志保留位置与关键结果，不全贴；一次通过不写成稳定保证 |
| 未完成项/阻碍 | 具体缺什么、影响什么、由谁解决、怎样证明关闭、当前可独立推进什么 | 需求有答案的不再问产品；工程事实不包装成用户选择 |
| 已废弃方案 | 只保留容易复活且会造成错误的方案、撤回理由与替代入口 | 无后续影响的思考、失败探索不加入正文 |

一项知识是否“够详细”：另一位接手者能解释**何时适用、为何这样、怎么落实、什么情况不能用、凭什么相信**。不要求每项硬套五个字段，但不得为了短而删去会改变判断的信息。

来源优先级依问题而定：用户决定产品范围，正式发布契约决定API，现场检查决定当前进程状态。不能用新旧时间戳代替权威判断；两份权威来源冲突时记录具体差异和受影响工作，不自行抹平。若仅有旧助手总结，标明未重新核实并引用它，不声称看过原文、截图或真实服务。

下一步依赖既有授权时，保留可追溯的任务原话或来源及适用范围，别只写“先前已经授权”。原话使用“这些/那几个”等指代而范围无法核实时，保留这项缺口，不自行扩大；它只影响依赖该范围的动作，不清零其他明确授权。

用户只在对话中给过的重要指令应记录来源、原意和必要原话；可写独立快照或放入知识正文，标明它是交接记录，不是自行新增的全局规则。未获得全量历史时说明掌握范围，继续完成可确定内容，不捏造“全部已核对”。

## 有效知识、原始证据与历史分开

详细正文呈现当前有效版本；原始契约、日志、旧报告保留可定位引用。不要在同一层并排摆放两条相反方案却不说明哪个有效，也不要删除原文来假装从无冲突。

可访问的正式文档优先引用到节/实体，并用简短说明保留关联关系；不机械复制全文。关键素材仅在对话中、位于临时目录、未跟踪或可能被重生成覆盖时，先安全落盘或记录必要快照，保留原来源及时间。独立快照要注明只代表当时，不冒充当前事实。需要凭据的来源仅记录获取方式和身份要求，不嵌入凭据。

示例：

- 有用：`用户确认“缺少业务维度时给合法候选，选定后查”；选择前不发替代查询；同维度唯一权威别名可绑定；旧“自动换维度”条款仅作历史。源：用户回复/契约节。`
- 不足：`维度逻辑已确认，见若干文件。`
- 噪音：按顺序复述三次讨论、每次搜索命令以及已被替代的建议，又不指出有效规则。

## 短入口是有目的的阅读路由

沿用现有命名即可。新交接通常可用：

- `ENTRY.md`：实际规则正文路径与作用范围、当前目标/状态、少量会改变下一步的关键约束、首个动作、按需阅读路由。
- `KNOWLEDGE.md`：详细有效知识；已有合格SPEC/调查文档时可由它们承接，不另复制。
- `START-HERE.txt`：可粘贴的开场，给入口绝对路径、实际接续任务、已有授权边界；不再复制一遍知识正文。
- `state.json`：仅当多仓/快照/易变状态值得做文件一致性检查时添加，不强制简单任务产生机器清单。

入口的路由应连接“接手者遇到的问题→具体位置→读取用途”，例如：

| 什么时候读 | 去哪里 | 读后要解决什么 |
|---|---|---|
| 开始改请求适配前 | 接口映射某节 | 明确字段来源、合法值和不支持的处理 |
| 对已确定选择产生疑问 | 决策记录对应条目 | 确认有效规则、例外和旧方案为何失效 |
| 准备真实验收时 | 验证计划与环境记录 | 核对账号/版本/数据/Oracle，分清未验范围 |
| 需要重新生成交付物 | 生成入口与来源约束 | 知道哪些源可改，避免旧生成器写回旧结论 |

不要将所有链接标“必读”；每个链接都写清用途。不要用一整页重复规则充当开场。常见阅读路线要直接指向相关节，不让接手者逐层打开许多索引。若某个细节会改变第一步，直接放入入口，不能藏在“可选历史”里。

下一会话有明确需要的技能时，可在对应阅读路由中给出“建议技能”：核对当前可用的名称或路径，写清何时使用、解决什么问题。不要照搬本会话用过的全部技能，也不要求接手者预先加载或安装它们；新环境中仍需确认可用性，缺少技能时先利用已有材料和工具推进可做部分。

对第一步的关键证据优先给直达链接，注明它是原始需求、正式发布契约、固定源码还是当前现场观察，避免将草案或源码存在当成已发布。若旧报告仍含已撤回待办，且确需引用它的其他证据，在链接附近说明失效范围并指向有效决定；不要要求接手者先读旧结论再自行纠偏。受保护的历史文件可以保持原样，通过外层注释区分，不为统一数字或状态重写证据。

## 规则入口的现场定位

从本会话已加载的规则、当前执行目录的适用入口及其明确引用定位规则正文；先核对候选路径存在且可读，再将实际来源写入交接。只查当前任务相关的目录与引用，不为找齐规则扫描全仓，也不按惯例假定某个标准文件名一定存在。

在短入口开头，用可直接打开的绝对路径列明当前适用正文、作用范围及核对时点。若规则入口只是引用、别名或跳转，同时直达正文并说明两者关系，不能只给一个仍需接手者继续猜的入口名。当前已知缺失的路径若会误导第一步，说明该缺口与实际可用来源，不罗列所有候选名称。

多仓或模块规则只记录已核对的适用范围；进入新的目标模块操作前，再读取其当前适用规则，不将工作区规则冒充全部模块规则。不同主机分别记录各自实际路径，不能从一台机器的目录推导另一台机器也存在相同文件。

若关键规则只在用户会话指令中提供且没有可读文件，保存带来源与适用范围的必要摘录，明确这是会话记录；无法核实的来源保留缺口，不虚构文件，也不为了补齐交接去创建或修改全局规则。新会话仍以当前用户要求和现场适用规则为准。

## 下一步与授权

记录原任务的停点、尚在运行的进程/测试/写入和真实结果。对不确定执行结果先只读核对，避免下一会话重复提交或重复启动。新任务已经替代旧任务时，旧待办标为背景，不再建议继续。

第一步应是有明确产出、前置和授权依据的动作，例如“核对已发布schema并补字段映射”，而不是“熟悉项目”。如果没有已授权的后续动作，给出建议并标明未授权，不伪造用户希望执行；已有授权则无需因交接重新请求。

已有交接可局部修订，复用正确正文；有实质规则/任务变更时更新有效入口和失效标记，保留必要历史来源。不要无限追加每轮对话，也不强制每次复制整个目录。交接文档不作为默认修改业务代码、TAPD或其他外部系统的请求。

## 认证与访问前置

只在下一步确实依赖登录、SSH 或受保护 API 时，记录足以定位既有访问方式的信息：

- 访问对象：实际目标环境、入口、账号及项目/租户/Scope。执行宿主机与被测环境分别注明，不能因在某台服务器运行就推断业务请求也指向它。
- 认证来源：现有受保护凭据文件的位置、凭据管理器条目、已配置的工具连接或 SSH 身份，以及取用所需权限。只记录实际已知来源；来源未知就明确写缺口，不杜撰文件或承诺可用。
- 可继承状态：哪些配置在新会话仍可访问，哪些临时登录态仅属于旧会话；已有可用性观察注明时点和验证范围。交接本身不要求重新登录或发送业务请求，未验证的有效性如实标明。
- 前置缺口：若来源、权限或重新登录仍待处理，说明阻塞哪一步、由谁提供什么；不让认证缺口阻塞不依赖它的工作。

不把密码、token、cookie、私钥正文、Secret 或含有这些内容的 URL、命令和截图写入交接包。凭据文件不纳入快照、hash 清单或原稿备份；也不因交接新建凭据存储、迁移口令或修改权限。需要用户补充时，说明缺少的安全取用入口，而不是在交接材料中复制旧会话的明文凭据。

## 最终回复与可复制开场

交出模式每次完成创建或更新后，简要说明落盘结果、关键未核实项，并链接实际入口；随后在最终回复中放一个独立的 `text` 代码块，让用户一次复制即可在新会话接续。不能只链接 `START-HERE.txt` 或让用户再要求生成开场。若保存了开场文件，文件正文与回复代码块保持一致。

开场以本次接续目标为中心，给出实际工作目录、入口绝对路径、真实停点和第一步；第一步有会改变执行的前置或关键约束时直接写出，其余细节交给入口按需引导。不要把完整知识库、所有规则或未经核实的“此前已授权”断言塞进开场。

下面只是写法示意，可按任务删减；实际交付须填入真实内容，不能留下占位符：

```text
使用 $session-handoff 接续以下工作。
工作目录：{实际绝对路径}。
先读交接入口：{实际入口绝对路径}，再按当前动作读取必要章节和原始证据。
适用规则：{实际规则正文路径及作用范围；或入口中已定位的来源与缺口}。
本次目标：{用户指定的下一会话重点，或仍有效的未完成目标}。
当前停点：{实际完成状态，以及影响下一步的未验证项}。
第一步：{有明确产出的具体动作及必要前置}。
关键边界：{会改变当前动作的约束；详细来源见入口}。
核对影响本次动作的当前状态，在可追溯的既有授权范围内继续；实质缺口再提问。
```

若工作已完成且用户未指定后续目标，明确完成状态，提供背景接续入口，不编造执行任务。若没有文件写入条件，则在同一代码块中直接提供目标、关键决定与来源、状态、缺口和第一步；说明未落盘，不写不存在的入口。跨环境交接还需写清哪些材料接手者无法直接访问，以及需要带走的脱敏内容。

## 可选机器清单

脚本不生成知识、总结或判断真伪；以下结构只用于列出的本地文件检查。路径可为清单所在目录的相对路径或绝对路径。远端URL写在正文中，不交给本地检查器当文件。

```json
{
  "version": 1,
  "entry": "ENTRY.md",
  "files": [
    {"path": "ENTRY.md", "kind": "artifact", "sha256": "实际文件SHA256"},
    {"path": "evidence/contract.json", "kind": "snapshot", "sha256": "实际快照SHA256"},
    {"path": "/workspace/spec.md", "kind": "live", "sha256": "生成交接时SHA256"},
    {"path": "/workspace/optional.log", "kind": "live", "required": false}
  ]
}
```

`artifact`是交接自产文件，`snapshot`是冻结证据，二者需hash且变化报错，提醒修订或恢复来源；`live`是可持续变化的项目材料，hash变化仅提示重读受影响来源，不能由旧快照否决后来有效修改。非必需源缺失也只提示。不要为了检查通过更新hash来掩盖未知变化。

清单可额外记录任务、决定、现场观察时间和状态；检查器不会证明这些语义正确。交接创建后修改内容，要先确认修改含义，再更新受影响清单记录。不要把清单自身放入带hash的files导致自引用。

## 交出前做一次接手审阅

只看开场文案和短入口，试定位实际规则正文、其作用范围、下一步及关键边界，确认不必先猜测规则文件名；再沿一个会影响实现或验证的问题走到详细材料，确认能找到足够细节和来源。对照用户最新目标、关键纠正和验收条件，确认每项会改变接续判断的内容都有正文或明确定位；已知缺口保留为缺口。最后核对被撤回方案不会被误读为待选、失败/未验不会读成完成、旧版本不会读成现行。

从新会话只拿到最终代码块的情形检查：能否找到入口、理解要继续什么并开始第一步；路径是否可访问，开场文件是否与文案一致。只给链接、遗留占位符或仍需用户补问“我要复制哪段”时，补全最终回复。

结构脚本只能补充上述审阅。需要更高置信时可用独立冷启动接手评估，但仅在可用且获准委派时采用，不默认创建新会话或子代理。真实评估不给预期答案，检查能否开始正确工作和暴露真实缺口，而不是检查是否照抄摘要。
